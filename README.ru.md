# ayla-tools-browse

Ограниченный инструмент `browse` для кодинг-агента Pi. Он ищет и читает
недоверенные веб-документы через
[ayla-tools-web](https://github.com/kekma-dot/ayla-tools-web) и отдаёт короткие
снимки с адресацией по строкам вместо целых страниц.

[English](README.md) · [Семейство Ayla tools](https://github.com/kekma-dot/ayla-tools) · [MIT](LICENSE)

## Установка

Требования: Pi 1.3.0, Node.js >= 22.19 и движок `ayla-tools-web` в том же профиле
Pi.

```bash
pi install git:github.com/kekma-dot/ayla-tools-web
pi install git:github.com/kekma-dot/ayla-tools-browse
```

`browse` читает документы через инструмент движка `web_document`, который
регистрируется только при включённых снимках. Добавьте ключ в
`~/.pi/agent/web-search.json` (или `$PI_CODING_AGENT_DIR/web-search.json`), не
заменяя текущие настройки, и перезагрузите сессию:

```json
{
  "documentSnapshots": true
}
```

```
/reload
```

После перезагрузки `browse` зарегистрирован. До инструментов движка
(`web_search`, `fetch_content`, `web_document`) он доходит через API вложенных
инструментов и активирует их сам. Своих ключей провайдеров у пакета нет: поиск и
загрузка используют настройки движка. Для загрузки страницы ключ поискового API
не нужен; требования к поиску зависят от провайдера. См.
[README движка](https://github.com/kekma-dot/ayla-tools-web/blob/main/README.ru.md#поисковые-бэкенды).

Удаление пакета не затрагивает движок:

```bash
pi remove git:github.com/kekma-dot/ayla-tools-browse
```

Pi 1.3.0 проверен как базовая версия; более новые выпуски Pi требуют повторной
проверки.

## Поверхность инструмента

| Параметр | Значение |
| --- | --- |
| `search_query` | 1-4 запроса: только ссылки, у каждого результата стабильный `s:` ref |
| `open` | 1-4 ref или URL: ограниченное окно строк, опционально `lineno`/`offset`/`refresh` |
| `find` | 1-4 поиска точного текста по сохранённому снимку |
| `click` | 1-4 нумерованные ссылки из открытого снимка |
| `screenshot` | принимается схемой и всегда возвращает ошибку unsupported |
| `response_length` | `short` (6000 символов), `medium` (12000), `long` (24000) |

Правила, которые инструмент соблюдает:

- Не больше 8 операций за вызов. Окно на операцию выводится из выбранного
  бюджета; вызов, которому не хватает места на читаемое окно, падает вместо
  выдачи обрывков.
- Ref неизменяемы: чтение ref никогда не перезагружает страницу. `refresh` просит
  движок сделать новый снимок, и тот получает новый ref.
- `d:` ref указывает на долговечный снимок движка, `s:` ref на ссылку из сохранённого
  результата поиска. Неизвестный ref даёт ошибку, а не скрытую перезагрузку:
  модель не может перечитать то, что ей не выдавали.
- Ref пишутся в ветку сессии (custom-запись `ayla-browse-refs-v1`), поэтому форк
  сессии сохраняет унаследованные ref. Не больше 1024 ref на ветку.
- URL только абсолютные HTTP(S), до 4096 символов, без встроенных учётных
  данных.

Вывод начинается с предупреждения, что содержимое страницы недоверенное и не
является инструкциями. Окна браузера и автоматизации страниц нет: страницы
приходят как HTML или текст по HTTP, `click` переходит по нумерованной ссылке
внутри уже открытого снимка, а сам пакет не исполняет JavaScript страницы
(настроенный reader-бэкенд может рендерить её на своём сервере). `screenshot`
возвращает ошибку unsupported: нативного рендерера canvas в пакете нет, а текст
PDF доступен через `open` и `find`.

## Безопасность и приватность

Пакет представляет собой тонкий слой только для чтения, своего сетевого кода у
него нет: каждый
поиск, загрузка и просмотр документа выполняются инструментом `ayla-tools-web`
через публичный API вложенных инструментов. Ключи провайдеров, SSRF-валидация,
неизменяемое хранилище снимков и ограничения вывода остаются в движке, включая
проверки loopback, приватных сетей и редиректов.

## Совместимость

- Публичный API расширений Pi 1.3.0 (`registerTool`, `outputSchema`,
  `ctx.executeTool`, `ctx.sessionManager`).
- Контракт `web_document` v1 (`contractVersion: 1`, `lines`/`links`/`ref`). Другая
  версия контракта даёт явную ошибку, а не догадки.
- Пакеты хоста объявлены только как peers; копий `@earendil-works/*` в пакете нет.

## Разработка

```bash
npm install
npm run typecheck
npm test
```

`npm test` запускает контрактный тест против заглушённой границы вложенных
инструментов: сеть и движок не нужны. `npm run verify:pair` загружает оба
расширения через настоящий загрузчик Pi 1.3 и локальный HTTP-сервер; для него нужен
checkout движка в `AYLA_TOOLS_WEB_PATH`.
