# ayla-tools-browse

Ограниченный инструмент `browse` для агента Pi. Он ищет и читает недоверенные
веб-документы через [ayla-tools-web](https://github.com/kekma-dot/ayla-tools-web)
и отдаёт модели короткие снимки страниц с адресацией по строкам, а не целые
страницы.

[English](README.md) · [Семейство Ayla tools](https://github.com/kekma-dot/ayla-tools) · [MIT](LICENSE)

- **Это не UI-браузер.** Нет окна, автоматизации страниц и кликов в настоящем
  браузере. `click` переходит по нумерованной HTTP-ссылке внутри уже открытого
  снимка.
- **Скриншотов нет.** Операция `screenshot` отвечает `PDF screenshot
  unsupported`: подходящего нативного рендерера canvas в пакете нет. *Текст* PDF
  доступен через `open` и `find`.
- **Никакого личного профиля.** Пакет ничего не читает с машины автора;
  конфигурация лежит в стандартном каталоге Pi.

## Установка

Требования: Pi **1.3.0** — проверенная базовая версия; более новые выпуски Pi
требуют повторной проверки — Node.js **>= 22.19** и движок `ayla-tools-web`,
установленный в тот же профиль Pi.

```bash
pi install git:github.com/kekma-dot/ayla-tools-web
pi install git:github.com/kekma-dot/ayla-tools-browse
```

Затем перезагрузите сессию, чтобы Pi подхватил пакет:

```
/reload
```

`browse` читает документы через инструмент движка `web_document`, который
регистрируется только при включённых снимках. Добавьте переключатель один раз в
`~/.pi/agent/web-search.json` (или `$PI_CODING_AGENT_DIR/web-search.json`) — если
файл уже существует, добавьте ключ к текущим настройкам, а не заменяйте файл, —
и перезагрузите снова:

```json
{
  "documentSnapshots": true
}
```

Проверьте, что инструмент `browse` доступен и что на месте инструменты движка
(`web_search`, `fetch_content`, `web_document`). В `ayla-tools-browse` нет
собственных ключей провайдеров: поиск и загрузка используют то, что настроено в
`ayla-tools-web`. Чистой установке **ключи не нужны для старта**: прямое чтение
публичных страниц работает без ключа, а zero-config поиск движка идёт через
бесключевой MCP-эндпоинт Exa — внешний сервис, чьи доступность и лимиты здесь
вживую не проверялись. Ключ провайдера добавляется только если вы выбрали этого
провайдера. Матрица провайдеров — в
[README движка](https://github.com/kekma-dot/ayla-tools-web/blob/main/README.ru.md#поисковые-бэкенды).

Удаление: `pi remove git:github.com/kekma-dot/ayla-tools-browse`.

## Поверхность инструмента

| Параметр | Значение |
| --- | --- |
| `search_query` | 1–4 запроса: только ссылки, у каждого результата стабильный `s:` ref |
| `open` | 1–4 ref или URL: ограниченное окно строк, опционально `lineno`/`offset`/`refresh` |
| `find` | 1–4 поиска точного текста по сохранённому снимку |
| `click` | 1–4 нумерованные ссылки из открытого снимка |
| `screenshot` | принимается схемой и всегда возвращает ошибку unsupported |
| `response_length` | `short` (6000 символов), `medium` (12000), `long` (24000) |

Что инструмент гарантирует:

- Не больше 8 операций за вызов; окно на операцию выводится из выбранного
  бюджета, и вызов, которому не хватает места на читаемое окно, падает вместо
  выдачи обрывков.
- Ref неизменяемы: чтение ref никогда не перезагружает страницу. `refresh` явно
  просит движок сделать новый снимок, и тот получает новый ref.
- `d:` ref — долговечный снимок движка, `s:` ref — ссылка из сохранённого
  результата поиска. Неизвестный `d:`/`s:` ref приводит к ошибке, а не к
  скрытой перезагрузке: модель не может перечитать то, что ей не выдавали.
- Ref пишутся в ветку сессии (custom-запись `ayla-browse-refs-v1`), поэтому
  форк сессии сохраняет унаследованные ref. Не больше 1024 ref на ветку.
- URL — только абсолютные HTTP(S), до 4096 символов, без встроенных учётных
  данных. Проверки loopback, приватных сетей и редиректов остаются в SSRF-защите
  движка; этот пакет их не ослабляет.

Вывод всегда начинается с предупреждения, что содержимое страницы — недоверенные
данные, а не инструкции.

## Модель безопасности

`ayla-tools-browse` — тонкий слой только для чтения поверх движка. У него нет
своего сетевого кода: каждый поиск, загрузка и просмотр документа выполняются
инструментом `ayla-tools-web` через публичный API вложенных инструментов. Ключи
провайдеров, SSRF-валидация, неизменяемое хранилище снимков и ограничения вывода
принадлежат движку.

## Совместимость

- Публичный API расширений Pi `1.3.0` (`registerTool`, `outputSchema`,
  `ctx.executeTool`, `ctx.sessionManager`).
- Контракт `web_document` **v1** (`contractVersion: 1`, `lines`/`links`/`ref`).
  Другая версия контракта приводит к явной ошибке, а не к догадкам.
- Пакеты, которые предоставляет хост, объявлены только как peers; копии
  `@earendil-works/*` в пакет не входят.

## Разработка

```bash
npm install
npm run typecheck
npm test
```

`npm test` запускает контрактный тест инструмента: настоящий `browse` работает
против заглушённой границы вложенных инструментов, поэтому сеть и движок не
нужны.

Поведение, которое требует движка, вынесено в release-гейты (запуск из этого
каталога):

```bash
npm run verify:install                               # pack, только production-зависимости, загрузчик Pi 1.3
AYLA_TOOLS_WEB_PATH=../ayla-tools-web npm run verify:pair
```

`verify:pair` загружает **оба** расширения через реальный загрузчик ресурсов
Pi 1.3, даёт faux-модели вызвать `browse` и проверяет, что вложенный вызов
движка возвращает настоящий снимок, прочитанный с локального HTTP-сервера. Без
checkout движка гейт завершается ошибкой, а не пустым успехом.
